# 第 11 章　开发计划与里程碑

> 以下按 **6 人团队**估算（Java Agent 2 人、后端 1.5 人、前端 1 人、安全研究 1 人、测试 0.5 人），可以根据实际人力调整。

## 11.1 阶段划分

| 阶段 | 周期 | 目标 | 主要交付 |
|---|---|---|---|
| M0 预研 | 第 1～3 周 | 吃透原理，跑通 Demo | 阅读 OpenRASP / jvm-sandbox 源码；完成一个 Hook 命令执行与 JDBC 的最小 Agent；确定技术选型 |
| M1 Agent 骨架 | 第 4～8 周 | 可加载、可隔离、可 Hook | launcher/bootstrap/core 三层结构、Spy、ASM 增强框架、请求上下文、阻断机制、本地配置、日志 |
| M2 检测能力 | 第 7～12 周 | P0 检测类型 | 首批检测类型（见第 2 章 P0）+ 规则用例集 + 靶场 |
| M3 平台 MVP | 第 6～12 周（并行） | 能管理、能看告警 | agent-api、console-api、alert-worker、前端（应用/实例/告警/策略/白名单）、docker-compose |
| M4 稳定性 | 第 12～15 周 | 达到生产标准 | 熔断、自监控、兼容性矩阵、性能基准、长稳测试、故障注入 |
| M5 试点 | 第 16～19 周 | 2～3 个真实业务试点 | monitor 模式运行，误报调优，运维手册 |
| M6 GA | 第 20 周 | 正式发布 v1.0 | 部分应用开启 block；K8s 注入；规则灰度 |
| 二期 | 之后 | 扩展 | attach 完善、内存马、SCA、IAST、Go/Python Agent、SIEM 深度对接 |

## 11.2 M0 预研建议任务

1. 写一个最小 Java Agent：`premain` + `ClassFileTransformer` + ASM，在 `ProcessBuilder.start` 前打印命令。
2. 让它在 Tomcat、Spring Boot fat jar 中都能工作，体会类加载器问题。
3. 把打印改成调用 Bootstrap 中的 Spy，体会隔离设计。
4. Hook JDBC，打印 SQL 和当前请求 URL（ThreadLocal）。
5. 阅读：OpenRASP `agent/java`、jvm-sandbox `sandbox-core`、jrasp-agent 的设计文档（见第 12 章）。

## 11.3 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 团队缺乏字节码/JVM 经验 | 进度延误、稳定性问题 | M0 预研充分；优先参考成熟开源实现；关键代码交叉评审 |
| 中间件/国产化环境兼容性 | 无法接入部分业务 | 提前收集公司技术栈清单（CMDB），按占比排优先级 |
| 误报影响业务信任 | 推广受阻 | 默认 monitor；灰度流程；一键加白；快速响应机制 |
| 性能顾虑 | 业务拒绝接入 | 公开性能报告；熔断机制；可按应用关闭 |
| 开源许可证 | 法务风险 | 借鉴设计，不直接复制代码；如果使用开源代码，评估许可证（OpenRASP 为 Apache-2.0，jrasp 部分为 GPL-3.0 或已闭源） |
| 维护成本 | 长期投入 | 规则与 Agent 解耦；CI 自动化兼容性测试 |

## 11.4 成功标准（v1.0）

- 接入应用 ≥ 50 个、实例 ≥ 500 个，连续 1 个月无 Agent 导致的 P1 故障。
- P0 检测类型在靶场中检出率 ≥ 95%，生产误报率 < 1%（按告警研判结果统计）。
- 性能指标满足第 2 章要求。
