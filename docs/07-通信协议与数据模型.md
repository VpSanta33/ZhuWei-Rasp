# 第 7 章　通信协议与数据模型

## 7.1 总体约定

- 传输：HTTPS（TLS 1.2+），首版使用 HTTP/1.1 + JSON；报文较大时启用 gzip。
- 前缀：`/agent/v1`。
- 与语言无关：所有语言的 Agent 共用同一套协议，通过 `language` 字段区分。
- 时间：毫秒时间戳（UTC）。
- 超时：连接 3s、读 5s；Agent 侧所有网络调用都在后台线程中执行。

## 7.2 认证

1. 每个应用有一对 `app_key` / `app_secret`（平台生成）。
2. 每个请求携带请求头：
   - `X-Rasp-AppKey`
   - `X-Rasp-AgentId`（注册后获得）
   - `X-Rasp-Timestamp`
   - `X-Rasp-Nonce`
   - `X-Rasp-Sign = HMAC-SHA256(app_secret, method + path + timestamp + nonce + sha256(body))`
3. Server 校验签名、时间偏差（±5 分钟），并用 Redis 防 nonce 重放。
4. 可选：内网高安全场景使用 mTLS。

## 7.3 接口

### 7.3.1 注册 `POST /agent/v1/register`

请求：

```json
{
  "agent_id": "uuid-生成并持久化在本地（容器场景每次启动重新生成）",
  "language": "java",
  "agent_version": "1.0.0",
  "app_name": "order-service",
  "env": "prod",
  "hostname": "order-7f9c-abc",
  "ips": ["10.1.2.3"],
  "pid": 12345,
  "os": "Linux 5.10 amd64",
  "runtime": { "name": "OpenJDK", "version": "17.0.9", "vm": "HotSpot" },
  "server": { "type": "tomcat", "version": "9.0.83" },
  "container": { "id": "", "k8s_namespace": "", "k8s_pod": "" },
  "start_mode": "premain",
  "started_at": 1731050000000
}
```

响应：

```json
{
  "code": 0,
  "data": {
    "agent_id": "uuid",
    "heartbeat_interval": 30,
    "config_version": "a1b2c3",
    "rules_version": "1.3.0"
  }
}
```

### 7.3.2 心跳 `POST /agent/v1/heartbeat`

请求：

```json
{
  "agent_id": "uuid",
  "config_version": "a1b2c3",
  "rules_version": "1.3.0",
  "status": "running",
  "metrics": {
    "cpu_percent": 1.2,
    "heap_used_mb": 42,
    "hook_count_1m": 120345,
    "check_avg_us": 35,
    "check_p99_us": 410,
    "alarm_dropped_1m": 0,
    "breaker_state": "closed"
  }
}
```

响应：

```json
{
  "code": 0,
  "data": {
    "config_changed": true,
    "rules_changed": false,
    "kill_switch": false,
    "commands": [ { "id": "cmd-1", "type": "dump_hooks" } ]
  }
}
```

`commands` 用于下发一次性指令（如上报 Hook 状态、立即扫描依赖、卸载），Agent 执行后通过 `/agent/v1/command/ack` 回执。

### 7.3.3 拉取配置 `GET /agent/v1/config`

响应 `data` 为**签名信封**（MVP 已实现）：

```json
{
  "alg": "ES256",
  "key_id": "4b6c2837f1e1813d",
  "payload": "{\"app_key\":\"ak_...\",\"issued_at\":1762591680528,\"mode\":\"block\",...}",
  "signature": "MEUCIQ...（base64 DER）"
}
```

- `payload` 是合成后配置的 JSON **字符串**（不是对象），Agent 对它的 UTF-8 字节原样验签，避免重新序列化导致字节不一致。
- 算法 ECDSA P-256 + SHA-256（JDK 11 自带 `SHA256withECDSA`，无需第三方库；Ed25519 需要 JDK 15+，所以 MVP 没有选用）。
- `app_key` 把配置绑定到应用：A 应用的配置不能被重放给 B 应用。
- `issued_at`（毫秒）防回滚：比当前生效配置旧的签名配置会被拒绝，攻击者无法重放一份截获的旧配置（例如当初的 `mode=off`）。
- 校验失败时 Agent **保留当前配置**，日志写 `REJECTED server config: ...`，并在心跳 `metrics.config_rejected` / `config_reject_reason` 中上报。
- 本地缓存 `cache/config.json` 保存的是整个信封，每次启动都会重新验签；验签失败就忽略缓存，回退到 `conf/policy.json`。

`payload` 解开后为合成后的完整配置：

```json
{
  "version": "a1b2c3",
  "mode": "monitor",
  "checks": {
    "sql":     { "enabled": true, "action": "block" },
    "command": { "enabled": true, "action": "block" }
  },
  "whitelist": [
    { "url": "/api/report/export", "match": "prefix", "types": ["sql"], "param": null }
  ],
  "block_response": { "status": 403, "content_type": "auto", "html": "...", "json": "..." },
  "breaker": { "cpu_percent": 20, "check_p99_ms": 5, "window_sec": 60, "recover_sec": 300 },
  "report": { "batch_size": 100, "flush_interval_ms": 2000, "sample_rate_log": 1.0 },
  "privacy": { "mask_headers": ["cookie", "authorization"], "mask_params": ["password", "pwd", "token"] }
}
```

### 7.3.4 拉取规则 `GET /agent/v1/rules?version=1.3.0`

- 响应为规则包（zip）+ 请求头 `X-Rasp-Rules-Sha256`、`X-Rasp-Rules-Signature`。
- Agent 使用内置公钥校验签名；成功后原子替换，并缓存到本地 `rules/` 目录。

### 7.3.5 上报告警 `POST /agent/v1/alarms`（批量）

```json
{
  "agent_id": "uuid",
  "events": [
    {
      "event_id": "uuid",
      "event_time": 1731050123456,
      "attack_type": "sql",
      "algorithm": "xxx",
      "action": "block",
      "confidence": 90,
      "reason": "可读的命中原因",
      "params": { "server": "mysql", "query": "...(已截断)" },
      "request": {
        "request_id": "xxx",
        "method": "GET",
        "url": "https://a.com/api/x",
        "client_ip": "1.2.3.4",
        "real_ip": "1.2.3.4",
        "headers": { "user-agent": "..." },
        "params": { "id": ["..."] },
        "body": "（前 N KB，已脱敏）"
      },
      "stack": ["com.x.Dao.query(Dao.java:42)", "..."]
    }
  ]
}
```

- 单批 ≤ 100 条或 ≤ 1MB；Server 只做校验后写入 Kafka 的 `rasp.alarm` topic，快速返回。
- 失败处理：Agent 指数退避重试 3 次，仍失败就写入本地 `alarm.log`，下次恢复连接时补报（有上限）。

### 7.3.6 其他上报

| 接口 | 内容 |
|---|---|
| `POST /agent/v1/dependencies` | 依赖清单：`{"items":[{group, artifact, version, file, path, sha1, source}]}`（source 为 pom / pom-shaded / manifest / filename），注册后延迟上报，变化或重新注册时再报，单次最多 5000 项 |
| `POST /agent/v1/logs` | Agent 自身错误日志（采样），用于远程排障 |
| `POST /agent/v1/command/ack` | 指令回执 |

## 7.4 Kafka Topic

| Topic | 生产者 | 消费者 | 分区键 |
|---|---|---|---|
| rasp.alarm | agent-api | alert-worker、SIEM | app_id |
| rasp.agentlog | agent-api | alert-worker | agent_id |
| rasp.dependency | agent-api | sca-worker（P1） | app_id |

## 7.5 错误码

| code | 含义 | Agent 行为 |
|---|---|---|
| 0 | 成功 | — |
| 401 | 签名错误/AppKey 无效 | 停止上报，每 10 分钟重试一次，本地记录日志 |
| 404 | agent_id 未注册 | 重新注册 |
| 429 | 限流 | 退避重试 |
| 5xx | 服务端错误 | 退避重试，继续使用本地配置 |

## 7.6 版本兼容

- 协议版本放在 URL 中（`/v1`）；新增字段必须向后兼容，Agent/Server 都需要忽略未知字段。
- Server 必须同时支持当前与前两个 Agent 大版本。
