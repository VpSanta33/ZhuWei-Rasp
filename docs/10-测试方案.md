# 第 10 章　测试方案

## 10.1 测试分层

| 层级 | 对象 | 工具 | 准入标准 |
|---|---|---|---|
| 单元测试 | 检测算法、SQL 词法分析、路径规范化、IP 判断、配置合成 | JUnit5、Go test | 核心算法覆盖率 ≥ 90% |
| 规则用例测试 | 每个算法的正例/反例集（`rules/testcases/`） | 自研 runner，CI 执行 | 正例 100% 命中；反例 0 误报 |
| 字节码增强测试 | 各 Hook 点在目标 JDK/驱动版本上是否增强成功、参数是否正确获取 | 集成测试 + `-Drasp.debug.dump=true` 导出增强后的 class，用 `javap` 校验 | 全部通过 |
| 集成测试 | Agent + 靶场应用 + Mock Server | Testcontainers、Docker | 全部通过 |
| 兼容性测试 | JDK × 中间件 × 框架矩阵 | CI 矩阵任务 | 见 10.2 |
| 性能测试 | 典型应用在 有/无 Agent 下的 RT、QPS、CPU、内存 | JMH（微基准）、wrk/JMeter（压测） | 满足第 2 章指标 |
| 稳定性测试 | 7×24 长稳、内存泄漏、线程泄漏、attach/detach 循环 | 压测 + JFR/MAT 分析 | 72h 无泄漏、无异常 |
| 故障注入 | Server 宕机、网络抖动、磁盘满、规则包损坏、Agent 内部异常 | toxiproxy、chaos 工具 | 业务无影响 |
| 攻防测试 | 由安全团队在授权的测试环境中使用靶场进行检测效果验证 | 内部靶场 + 公开漏洞环境（如 vulhub） | 检出率达标，误报可控 |
| Server 测试 | API、权限、并发写入、容量 | Go test、k6 | 满足容量指标 |

## 10.3 靶场

在 `vuln-range/` 下维护一个 Spring Boot 靶场应用，覆盖第 1.4 节表格中的每种检测类型，每个漏洞对应一个接口，并配有：

- 正常请求用例（验证不误报）；
- 由安全团队维护的检测验证用例（不放在公开仓库，测试环境内部使用）。

靶场**只能部署在隔离的测试网络中**，严禁接入生产或公网。

## 10.4 性能基准方法

1. 选取 3 类基准应用：纯 CPU 计算型、典型 CRUD（DB 密集）、文件/网络 I/O 密集。
2. 对比 4 组：无 Agent / Agent off / monitor / block。
3. 每组预热 5 分钟，再压测 10 分钟，取 3 次平均值。
4. 记录 RT（avg/P99）、QPS、CPU、堆内存、GC 次数、启动耗时。
5. 结果自动归档，用于版本间回归对比（性能回退 > 2% 即阻止发布）。

## 10.5 发布门禁

- 单元测试 + 规则用例 + 集成测试全部通过。
- 兼容性矩阵核心组合通过。
- 性能回归 ≤ 2%。
- 新增 Hook 点需要经过 72h 长稳测试。
