# 第 13 章 上线检查清单

> 适用版本：v0.1.0（MVP）。本章区分“平台已具备的能力”和“上线前必须由团队完成的事项”。打勾项全部完成前，不建议对生产流量开启阻断模式。

## 13.1 结论先行

| 范围 | 状态 |
|---|---|
| 管理平台（Server） | **可用于生产部署**：多用户与角色、审计、策略签名、限流、健康检查与指标、在线备份、漏洞匹配、部署套件均已实现并经过测试 |
| Java Agent | **可用于观察模式试点**：接入、Hook、上下文、熔断、签名验签、安装卸载已验证；检测能力仅有通用规则 |
| 检测算法（第 5 章） | **未完成，阻断上线的前提**：需安全团队按 `Detector` 接口实现各攻击类型的专用算法并完成误报评估 |
| 控制台前端 | 现有页面可用；用户管理、API Token、漏洞列表等新能力目前只有 API，没有页面 |

## 13.2 上线前必须完成（团队负责）

- [ ] **检测算法**：按第 5 章实现并通过攻防测试集（第 10 章）；误报率在观察模式试点中达到团队标准。
- [ ] **试点**：选 2–3 个非核心应用，观察模式运行至少 2 周，记录性能影响（第 9 章预算）与误报，处理白名单。
- [ ] **灰度阻断**：按第 8 章 8.4 流程逐个应用开启阻断；开启时平台要求输入应用名确认，审计日志记录生效规则。
- [ ] **安全评审**：对平台部署环境做一次评审（网络隔离、TLS 证书、密钥保管、备份介质）。
- [ ] **应急演练**：演练一次全局紧急开关、`/opt/rasp/DISABLE` 文件、`rasp-attach.sh detach`、Agent 卸载，确认负责人和联系方式。

## 13.3 平台部署检查

| 检查项 | 做法 | 验证 |
|---|---|---|
| TLS | `-tls-cert/-tls-key` 或前置 TLS 代理；`RASP_AGENT_URL` 使用 `https://` | 启动日志无 `CONFIG WARNING` |
| 首个管理员 | 首次启动用 `RASP_ADMIN_PASSWORD`（≥ 12 位）创建，之后从环境文件中删除 | `rasp-server user list` |
| 账号与角色 | 为每个人建独立账号（或配置 LDAP/AD 按组映射角色，`ldaps://`）：`admin`（设置/紧急开关/用户/删除应用）、`operator`（研判、白名单、策略、导入漏洞）、`viewer`（只读，看不到 App Secret） | `GET /api/v1/users` |
| 集成凭证 | SIEM/CI 用 API Token（`POST /api/v1/tokens`，最长 366 天，只显示一次），不要共用登录口令 | `GET /api/v1/tokens` |
| 签名私钥 | `rasp-sign.key` 权限 600（否则平台拒绝启动），单独备份 | 启动日志 key id 与 Agent 配置一致 |
| 数据目录 | 数据库文件自动收紧为 600；目录 700，属主为服务账号 | `ls -l /var/lib/rasp` |
| 备份 | `rasp-backup.timer` 每日在线备份（含 `-with-key`），保留 14 天；定期做一次恢复演练 | 恢复到测试机后能登录、Agent 能验签 |
| 监控 | `RASP_OPS_LISTEN=127.0.0.1:9480`，Prometheus 抓取 `/metrics`；探针用 `/healthz`（存活）与 `/readyz`（数据库可用） | 见 13.5 告警规则 |
| 限流 | `RASP_ALARM_RATE`（默认每应用 100 条/秒，突发 10 倍），超出的告警丢弃并计数，Agent 本地 `alarm.log` 仍保留 | `rasp_alarms_rate_limited_total` |
| 漏洞数据 | 每日下载 OSV Maven 数据并 `rasp-server import-osv`（第 8 章 8.3.4） | `GET /api/v1/vulns/summary` 中 `last_import` |
| Webhook | 使用 HTTPS 地址；默认只推送阻断事件和高危/严重漏洞 | 发送一条测试告警 |

部署方式任选：`deploy/server/rasp-server.service`（systemd，已加固）或 `server/Dockerfile`（distroless、非 root，数据在 `/data` 卷）。

## 13.4 Agent 部署检查

- [ ] 使用 `tools/install.sh --properties <控制台生成的配置> --app-user <应用用户>` 安装；`conf/` 为 640、属主 root。
- [ ] `conf/rasp.properties` 中有 `policy.public_key`（策略验签），`server.url` 为 `https://`。
- [ ] 新应用保持观察模式；确认 `logs/rasp.log` 无 ERROR，实例在“下发状态”中显示已同步。
- [ ] 记录基线：接入前后接口 P99、CPU、堆内存（第 9 章预算：P99 增量 < 5%）。
- [ ] JDK 版本 ≥ 8；JDK 8 上动态 attach 需使用完整 JDK（含 `lib/tools.jar`）；JDK 21+ 动态 attach 需 `-XX:+EnableDynamicAgentLoading`，生产优先使用 `-javaagent`。

## 13.5 建议的监控告警

| 指标 | 告警条件 | 含义 |
|---|---|---|
| `up{job="rasp"}` / `/readyz` | 失败 > 2 分钟 | 平台不可用或数据库异常（Agent 不受影响，继续本地记录） |
| `rasp_instances_online / rasp_instances` | 明显下降 | Agent 失联、网络或证书问题 |
| `rate(rasp_alarms_rate_limited_total[5m])` | > 0 持续 | 某应用告警洪泛：可能遭受攻击或规则误报 |
| `rasp_kill_switch` | = 1 超过 1 小时 | 紧急开关未恢复，防护处于关闭状态 |
| `rasp_vulnerable_findings{severity="critical"}` | 上升 | 新发现严重漏洞组件 |
| `rate(rasp_console_login_failures_total[10m])` | 突增 | 口令爆破（单 IP/用户 15 分钟 10 次后锁定） |
| `rate(rasp_http_requests_total{code="5xx"}[5m])` | > 0 持续 | 平台内部错误，查看日志 |

## 13.6 容量与性能（实测）

测试环境：单机 Apple Silicon 笔记本，单个 `rasp-server` 进程，SQLite（WAL），数据库内 69 万～80 万条告警，启用告警全文索引。

| 场景 | 结果 |
|---|---|
| Agent 心跳（200 实例、50 并发） | ~10,800 次/秒，P99 11 ms → 按 30 秒心跳约可支撑 30 万实例的心跳负载 |
| 告警写入（每批 50 条、20 并发） | ~7,200 条/秒，P99 0.8 s（未建全文索引时 ~18,000 条/秒；按单节点设计目标“每天数千万条”仍有约 30 倍余量） |
| 总览统计 `/stats`（汇总表） | P50 7 ms、P99 13 ms（优化前全表扫描为 7.4 秒） |
| 告警列表（按类型+动作过滤、分页） | P50 20 ms |
| 告警列表（不过滤，首页） | P50 77 ms |
| 告警关键字搜索：命中少量记录（如查某个 IP、不存在的串） | 1–2 ms（全文索引；此前全表扫描 1.8 秒） |
| 告警关键字搜索：几乎命中全部记录的宽泛词 | ~1.2 秒 |
| 全文索引首次建立（升级时一次性，69 万条） | 5.6 秒 |
| 69 万条告警的汇总表回填（升级时一次性） | 2.6 秒 |

建议：单实例平台适合数百到数千个 Agent、告警保留 180 天以内的规模。告警量持续超过每天数千万条，或需要高频全文检索时，按第 3、6 章设计迁移到 MySQL + ClickHouse/Kafka。

## 13.7 已知限制

- 检测能力：仅通用规则（“用户输入流入危险函数”），无各攻击类型的专用算法。
- 关键字搜索：3 个字符以上走全文索引，1–2 个字符仍为全表扫描；几乎命中全部记录的宽泛词约 1 秒。
- 单实例、单机 SQLite，无多活；依赖每日备份 + 恢复演练保障数据。
- 控制台未提供用户管理、Token、漏洞列表页面（API 已提供）；前端未按角色隐藏按钮，越权操作会得到 403 提示。
- Agent：支持 JDK 8+（JDK 8 的运行时验证在 CI 中进行）；无内存马检测；不覆盖重写 `run()` 的 Thread 子类与虚拟线程的上下文传递。
- Docker 镜像与 systemd 单元已编写，但本次未在真实容器/Linux 主机上构建验证，首次使用请在测试环境确认。
