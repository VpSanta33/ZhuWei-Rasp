# 第 8 章　部署与运维

## 8.1 Agent 安装包结构

```
/opt/rasp/
├── rasp-launcher.jar
├── rasp-bootstrap.jar
├── rasp-core.jar
├── conf/rasp.properties   # MVP 使用 properties（设计稿为 rasp.yaml）
├── conf/policy.json       # 独立模式下的策略
├── cache/                 # 平台下发配置的本地缓存
├── logs/                 # rasp.log、alarm.log、dependencies.json（组件清单）
├── tools/
│   ├── rasp-attach.sh     # 对运行中 JVM 执行 attach / detach（已实现）
│   ├── install.sh         # 修改启动脚本 / 设置环境变量（未实现）
│   └── uninstall.sh       # （未实现）
└── VERSION                # （未实现）
```

## 8.2 接入方式

### 8.2.1 启动参数（推荐，最稳定）

```bash
JAVA_OPTS="$JAVA_OPTS -javaagent:/opt/rasp/rasp-launcher.jar -Drasp.app.name=order-service"
```

- Tomcat：`bin/setenv.sh` 中追加。
- Spring Boot fat jar：`java -javaagent:... -jar app.jar`。
- WebLogic/WebSphere/TongWeb：修改对应的启动脚本或控制台中的 JVM 参数（`install.sh` 自动识别常见中间件）。

也可以通过 `JAVA_TOOL_OPTIONS` 环境变量全局注入（注意：这会作用于该环境下所有 java 进程，需要在 launcher 中按进程名/主类做过滤）。

### 8.2.2 动态 attach（无需重启）

已实现（v0.1.0），工具内置在 `rasp-launcher.jar` 中，`tools/rasp-attach.sh` 是包装脚本（默认使用目标进程自己的 java）：

```bash
/opt/rasp/tools/rasp-attach.sh list                                   # 列出本用户的 Java 进程
/opt/rasp/tools/rasp-attach.sh status <pid>                           # 查看是否已注入
/opt/rasp/tools/rasp-attach.sh attach <pid> --app order-service --env prod
/opt/rasp/tools/rasp-attach.sh detach <pid>                           # 卸载，恢复原始字节码
```

等价的直接调用：`java -jar /opt/rasp/rasp-launcher.jar attach <pid>`。

- 重复 attach 是幂等的；升级 Agent 时先 detach 再 attach 新版本。
- detach 会停止检测、恢复被增强的类、停止全部 Agent 线程。`Spy` 桩类留在 BootstrapClassLoader 中无法卸载（只是空操作），再次 attach 时复用。
- 已验证（JDK 27 + Tomcat 10 演示应用）：注入后各 Hook 生效、告警上报、阻断；卸载后不再检测、业务正常、Agent 线程数归零；再次注入正常。
- 必须以与目标 JVM **相同的用户**执行，且运行工具的 Java 必须是包含 `jdk.attach` 模块的完整 JDK。
- 局限：无法 Hook native 方法的首次定义（见 4.3.3），部分 Hook 降级；JDK 21+ 动态加载 Agent 会打印警告（未来版本可能需要 `-XX:+EnableDynamicAgentLoading`）。
- 适合紧急防护（例如爆发 0day 时）或 POC，长期运行建议改为启动参数方式。

### 8.2.3 容器 / Kubernetes

| 方式 | 说明 |
|---|---|
| 基础镜像内置 | 公司 Java 基础镜像预置 `/opt/rasp`，通过环境变量 `RASP_ENABLE=true` 控制是否在 `JAVA_TOOL_OPTIONS` 中追加 |
| InitContainer + 共享卷 | initContainer 把 Agent 复制到 emptyDir，主容器挂载后设置 `JAVA_TOOL_OPTIONS` |
| Mutating Admission Webhook（推荐规模化使用） | 给打了 `rasp.zhuwei/inject: "true"` 标签/注解的 Pod 自动注入上面的 initContainer 和环境变量，业务零改动 |

应用标识在 K8s 中建议取自 `app` label 或 Deployment 名，通过 Downward API 注入环境变量 `RASP_APP_NAME`。

### 8.2.4 rasp-daemon（主机模式，可选）

- 以 systemd 服务运行，周期扫描 `/proc` 发现 Java 进程，根据平台下发的“应用匹配规则”（进程命令行正则）自动 attach。
- 负责 Agent 包的下载与校验、升级、卸载。

## 8.3 管理平台部署

### 8.3.1 POC / 小规模：docker-compose

包含：mysql、redis、kafka（KRaft 模式）、clickhouse、agent-api、console-api、alert-worker、web(nginx)。单机 8C16G 可支持约 500 个实例。

### 8.3.2 生产：Kubernetes + Helm

| 组件 | 副本 | 资源（起步） |
|---|---|---|
| agent-api | 3+（HPA） | 2C4G |
| console-api | 2 | 1C2G |
| alert-worker | 2+（与 Kafka 分区数匹配） | 2C4G |
| web | 2 | 0.5C512M |
| MySQL | 主从 / 云 RDS | 4C8G |
| Redis | 哨兵 / 云 Redis | 2G |
| Kafka | 3 broker | 4C8G |
| ClickHouse | 2 分片 × 2 副本（按数据量） | 8C32G |

- agent-api 前置 SLB/Ingress，单独域名（例如 `rasp-agent.company.com`），开放给全部业务网段。
- console 域名仅对办公网开放。

### 8.3.3 策略签名密钥（MVP 已实现）

- Server 启动参数 `-sign-key`（环境变量 `RASP_SIGN_KEY`），默认 `<数据库目录>/rasp-sign.key`；文件不存在时自动生成（权限 0600），并写出公钥 `rasp-sign.key.pub`。
- 控制台“应用详情”生成的 `rasp.properties` 已包含 `policy.public_key=...`；也可通过 `GET /api/v1/signing` 查询 key_id 和公钥。
- **私钥必须备份**：丢失后所有固定了旧公钥的 Agent 都会拒绝新配置（继续使用本地缓存或 `conf/policy.json`，不影响业务）。
- **轮换**：`policy.public_key` 支持逗号分隔多个公钥。① 先把“旧公钥,新公钥”分发到所有主机；② 再把 Server 的 `-sign-key` 换成新私钥并重启；③ 确认实例心跳中 `config_rejected` 不再增长后，删掉旧公钥。
- `policy.require_signature`：默认“配置了公钥就强制验签”；设为 `true` 而未配置公钥时，拒绝所有平台配置；未配置公钥时 Agent 接受未签名配置并打印一次警告（仅用于从旧版本升级）。
- `conf/policy.json` 不验签：它和 `rasp.properties`（公钥就在里面）一样，靠安装目录的文件权限保护。

## 8.4 上线流程（灰度）

```
1. 测试环境接入，回归测试通过
2. 生产 1~2 个实例 monitor 模式，观察 3~7 天（性能、告警、误报）
3. 扩大到该应用 100% 实例 monitor 模式
4. 处理误报、加白
5. 先对高置信度类型（命令执行、反序列化、JNDI 等）开 block
6. 逐步开启其他类型的 block
```

平台需要支持“按应用、按检测类型”分别设置模式，以配合这个流程。

## 8.5 升级与回滚

| 对象 | 方式 | 回滚 |
|---|---|---|
| 规则 | 平台灰度发布（按应用或比例）→ 全量 | 一键回滚到上一版本，Agent 下次心跳生效 |
| 配置 | 即时生效 | 历史版本对比与恢复 |
| Agent | 替换安装目录中的 jar，重启后生效；attach 模式可在线替换 | 保留上一版本目录 `/opt/rasp/versions/<ver>`，用软链接切换 |
| Server | 滚动发布；数据库迁移必须向后兼容 | Helm rollback |

## 8.6 降级与应急预案

| 场景 | 措施 | 生效时间 |
|---|---|---|
| 某应用误拦截 | 平台将该应用切到 monitor，或对该 URL 加白 | ≤ 30s |
| 大面积异常 | 全局 kill switch → 所有 Agent 关闭检测（Hook 变为空操作） | ≤ 30s（推送通道下秒级） |
| Agent 导致业务异常且 Server 不可达 | 本地创建文件 `/opt/rasp/DISABLE`（Agent 周期检查该文件），或 attach 卸载；最后手段是删掉启动参数后重启 | 秒级 / 重启 |
| Server 宕机 | Agent 使用本地缓存的配置和规则继续运行，告警写本地文件 | 无影响 |

## 8.7 监控

- Server 暴露 `/metrics`（Prometheus）：QPS、延迟、Kafka 积压、写库失败数、在线实例数。
- Agent 指标通过心跳汇总到平台，并转换成 Prometheus 指标：检测耗时 P99、熔断实例数、上报丢弃数。
- 告警规则示例：在线率下降 > 10%、熔断实例数 > 5、Kafka 积压 > 10 万。
