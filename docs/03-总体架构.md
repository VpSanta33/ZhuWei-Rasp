## 3.2 模块说明

### Agent 侧

| 模块 | 制品 | 职责 |
|---|---|---|
| rasp-launcher | `rasp-launcher.jar` | 入口，含 `premain`/`agentmain`；负责定位安装目录、把 bootstrap 包加入 BootstrapClassLoader、创建 RaspClassLoader 加载 core |
| rasp-bootstrap | `rasp-bootstrap.jar` | **只放极少的类**：`Spy`（插桩代码调用的静态入口）、Hook 回调接口、阻断异常类型。必须在 Bootstrap CL 中，否则 `java.*` 类的插桩代码找不到它 |
| rasp-core | `rasp-core.jar` | 全部实现逻辑，运行在独立的 `RaspClassLoader` 中，与业务类隔离；依赖（ASM、JSON、Netty 等）全部 shade 重命名 |
| rasp-rules | `rules-x.y.z.zip`（签名） | 检测规则/插件，可热更新 |
| rasp-daemon | 二进制（Go） | 可选：主机上的守护进程，负责自动发现 JVM、attach、升级、拉包；也可以兼顾以后多语言 Agent 的注入 |

### Server 侧

| 服务 | 语言 | 职责 |
|---|---|---|
| agent-api | Go | 面向 Agent：注册、心跳、配置/规则下发、告警与日志接收（写入 Kafka）。高 QPS，无状态 |
| console-api | Go | 面向控制台：应用/实例/策略/规则/告警/用户等 CRUD、鉴权、审计 |
| alert-worker | Go | 消费 Kafka：告警解析、去重聚合、入库 ClickHouse/ES、触发通知、外发 SIEM |
| web | Vue3 + TypeScript + Element Plus/Ant Design Vue | 控制台前端 |
| scheduler | Go（可并入 console-api） | 定时任务：离线判定、数据清理、报表、漏洞库同步 |

## 3.3 技术选型

| 项 | 选型 | 理由 / 备选 |
|---|---|---|
| Agent 字节码框架 | **ASM 9.x**（shade） | 体积小、性能最好、可精细控制；Byte Buddy 开发效率更高，但体积大，在 JDK 内部类上需要更多 trick |
| Agent JSON | 自研轻量实现或 shade 后的 Gson | 避免与业务的 fastjson/jackson 冲突 |
| Agent 通信 | JDK 原生 `HttpURLConnection` + 自管理线程池（HTTPS） | 零依赖、稳定；后续可换 gRPC（需要 shade Netty，体积约 +5MB） |
| 规则执行 | **Java 原生实现检测算法 + 声明式规则配置（YAML/JSON）**；可选嵌入 JS 引擎（Rhino/GraalJS）运行自定义插件 | OpenRASP 用 JS 插件的好处是热更新和跨语言共用，代价是性能和体积。建议核心算法用 Java 写，可调参数放规则文件，复杂自定义逻辑用插件（见第 5 章） |
| 后端语言 | **Go 1.22+** | 高并发、部署简单；团队以 Java 为主的话也可以用 Spring Boot |
| Web 框架 | Gin / Kratos | — |
| 配置库 | MySQL 8 | — |
| 告警/日志库 | **ClickHouse**（量大、以聚合分析为主）或 Elasticsearch（全文检索强） | 二选一，推荐 ClickHouse，成本更低 |
| 消息队列 | Kafka | 削峰；同时方便 SIEM 订阅 |
| 缓存 | Redis | 在线状态、心跳、限流、分布式锁 |
| 前端 | Vue3 + Vite + TS | — |
| 部署 | Docker + K8s（Helm Chart） | 同时提供单机 docker-compose 版本，便于 POC |

## 3.4 核心数据流

### 3.4.1 启动与注册

1. JVM 以 `-javaagent:/opt/rasp/rasp-launcher.jar` 启动，或由 daemon attach。
2. launcher 加载 core，core 读取本地 `conf/rasp.yaml`（Server 地址、AppKey 等）。
3. core 向 agent-api 发送 `register`，带上主机名、IP、PID、JDK、中间件、Agent 版本、应用标识。Server 返回 `agent_id` 和初始配置与规则版本。
4. core 注册 Transformer，对已加载的目标类执行 `retransformClasses`。
5. 进入运行状态，开始心跳（默认 30s 一次）。

### 3.4.2 请求检测

1. 请求进入：Hook `HttpServlet.service` / `FilterChain.doFilter` → 创建 `RequestContext` 放入 ThreadLocal。
2. 业务调用敏感函数 → 插桩代码调用 `Spy.onEnter(hookId, args)` → core 中对应 Hook 处理器组装 `CheckParams`。
3. 检测引擎按检测类型执行规则 → 返回 `PASS / LOG / BLOCK`。
4. 结合白名单与策略决定最终动作；`BLOCK` 时抛出 `RaspBlockException`，并在请求入口处统一捕获，输出拦截页面。
5. 告警放入有界队列 → 异步批量上报 → Kafka → alert-worker → 入库 → 通知。
6. 请求结束：清理 ThreadLocal（必须在 finally 中做）。

### 3.4.3 配置与规则下发

- **拉模式（推荐首版）**：心跳响应中带上 `config_version`、`rules_version`，Agent 发现版本不同就拉取全量。
- **推模式（可选）**：长连接/WebSocket 推送，用于紧急关停，可以秒级生效。
- 规则包需要**签名校验**（Ed25519），校验失败就拒绝加载，继续使用旧版本。

## 3.6 扩展性设计（为二期预留）

- **多语言**：Server 侧协议与语言无关（见第 7 章），`agent.language` 字段区分；检测算法中与语言无关的部分（SQL 词法分析、SSRF IP 判断、路径规范化）建议沉淀为**跨语言规范 + 共享测试用例**。
- **IAST**：Hook 框架预留 `source / propagator / sink` 三类 Hook，RequestContext 预留污点存储。
- **SCA**：Agent 上报 jar 清单（文件名、Maven 坐标、SHA1），Server 侧匹配漏洞库。
