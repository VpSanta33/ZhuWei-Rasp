# 第 2 章　需求与范围

## 2.1 建设目标

1. 为公司 Java Web 应用提供生产级的运行时攻击检测与阻断能力。
2. 能大规模接入（目标 ≥ 5000 个 JVM 实例），统一管理策略、统一查看告警。
3. 对业务基本无感：平均 RT 增加 < 5%，CPU 增加 < 5%，堆内存增加 < 100MB。
4. 与公司现有安全体系对接：SOC/SIEM、工单、IM 告警、CMDB。

## 2.2 角色

| 角色 | 主要诉求 |
|---|---|
| 安全运营 | 查看告警、研判、加白、切换防护模式、导出报表 |
| 安全研究 | 编写/调试检测规则，发布规则版本 |
| 业务开发 | 看到自己应用的告警和调用栈，定位漏洞代码 |
| 运维/SRE | 批量安装、升级、卸载 Agent，监控 Agent 健康，紧急关停 |
| 管理员 | 用户、权限、租户/部门管理，审计 |

## 2.4 非功能需求

| 类别 | 指标 |
|---|---|
| 性能（Agent） | 单次 Hook 检测 P99 < 1ms；整体 RT 增加 < 5%；CPU 增加 < 5%；稳定运行时堆内存增加 < 100MB；启动时间增加 < 10s |
| 稳定性（Agent） | Agent 内部任何异常都不得抛到业务代码（阻断异常除外）；不得造成死锁或 OOM；与 Server 失联时业务不受影响 |
| 兼容性 | JDK 8、11、17、21（JDK 6/7 视需要作为 P2）；Tomcat 7～10、Jetty、Undertow、WebLogic、WebSphere、JBoss/WildFly、TongWeb、BES；Spring Boot 1.x～3.x；HotSpot、OpenJ9、毕昇、龙井等 |
| 容量（Server） | 5000 个实例在线；心跳 QPS ≥ 200；告警写入峰值 ≥ 5000 条/秒；告警保留 180 天 |
| 可用性（Server） | 99.9%；无状态服务可水平扩展；Server 故障时 Agent 继续按最后一次配置工作 |
| 安全 | Agent↔Server 全程 TLS；Agent 身份认证；规则包签名校验；平台 RBAC + 审计；敏感字段（Cookie、密码）脱敏 |
| 可运维 | Agent 自身日志可分级、可滚动；指标暴露给 Prometheus |

## 2.5 不在本期范围内

- 非 Java 语言 Agent（规划为二期）。
- 业务逻辑漏洞（越权、薅羊毛等）防护。
- CC/DDoS 防护（由 WAF/高防负责）。
- 移动端 App 自保护（RASP 的另一个含义，与本项目无关）。
